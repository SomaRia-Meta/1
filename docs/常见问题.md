# 常见问题

## 「组件库没有签名有效的 sppsvc.exe」

说明 `C:\Windows\WinSxS` 里也没有干净副本了。两种可能：

1. **一份都没扫到** —— 组件库被清空或严重破坏
2. **扫到但全是 ✗** —— 篡改工具原地修改了文件，硬链接让组件库一起变脏

两种都必须走 **④ 联网修复**，让 `DISM` 从 Windows Update 重新落地一份组件。

---

## ④ 联网修复报 `0x800f081f`

这个错误码含义是"找不到源文件"，通常不是网络断了，而是 Windows Update 不可用。检查顺序：

1. `Windows Update`（wuauserv）和 `BITS` 两个服务是否在运行
2. 是否被组策略限制：`计算机配置 → 管理模板 → Windows 组件 → Windows 更新`
3. 是否被第三方"系统优化"工具关掉了更新（有些 .reg 会直接改这些策略）

都排除后，可以用本地 ISO 作为源：

```bat
dism /Online /Cleanup-Image /RestoreHealth /Source:D:\sources\install.wim:1 /LimitAccess
```

其中 `D:` 是挂载 ISO 后的盘符，`install.wim` 也可能是 `install.esd`。

---

## 修复后仍显示未激活

按顺序试：

1. **③ 深度修复** —— `slmgr /rearm` 重置授权状态
2. **重启电脑**，再运行一次 ②
3. 确认能上网，然后 `slmgr /ato`（工具里已包含）
4. **⑤ 保资料重装**

如果系统本来就是 KMS 私服激活的，那修复后需要合法授权——**这不是工具能解决的**。

---

## 提示「在运行非核心版本的计算机上运行 slui.exe」（0xC004F069）

这是**密钥与系统版本不匹配**。典型场景：在家庭版上装了专业版的 KMS 密钥。

诊断页的「密钥与版本匹配分析」会直接告诉你：

```
当前密钥末五位 [XXXXX] 与「家庭版」应有的 [H8Q99] 不一致
```

正确的做法不是换密钥，而是**先确认你到底装的是哪个版本**：

- 如果本来就该是家庭版 → 别装 KMS 密钥，用数字许可证激活
- 如果确实要专业版 → 需要合法的专业版授权，用 KMS 密钥改版本只会把系统弄坏

---

## 家庭版能不能用这个工具升级成专业版？

**不能，也不该这么做。**

Windows 的版本（Edition）由安装的系统映像决定，不是改注册表或换个密钥就能变的。第三方工具所谓的"版本转换"实际上是改 `EditionID` 注册表值，会导致：

- 系统组件与版本标识不一致
- Windows 更新失败
- 激活反复失效（就是本文档描述的症状）

真正的升级需要用专业版密钥通过「设置 → 激活 → 更改产品密钥」走官方升级流程，或者用专业版 ISO 做升级安装。

---

## 修复完要不要删那个 KMS 工具？

**建议删除。** 这类工具普遍附带：

- 关闭 Windows Defender 的注册表脚本
- 关闭 SmartScreen / 安全中心通知
- 修改 Windows Update 策略
- 注入的证书或服务

本次案例中的 `DragonKMS` 目录里就有 `Remove_Defender\` 一整套 .reg 文件。留着它，下次系统更新可能又出问题。

删完之后建议跑一次全盘杀毒。

---

## 修复会不会影响我的文件？

| 操作 | 对个人文件的影响 |
|---|---|
| ①②③ 修复 | 完全不影响，只动 `sppsvc.exe` 一个文件和授权状态 |
| ④ 联网修复 | 不影响，DISM/SFC 只处理系统文件 |
| ⑤ 保资料重装 | 不删除个人文件、已装软件、用户配置 |

⑤ 虽然不删数据，但升级过程中会在 `C:\` 下创建 `$WINDOWS.~BT` 和 `Windows.old`，需要 20 GB 以上空间。升级成功后 `Windows.old` 可以手动清理。

---

## 工具需要管理员权限吗？

需要。所有涉及 `System32` 写入、服务控制、`DISM`/`SFC` 的操作都必须提权。

`run-fix.bat` 会自动请求提权；如果你想手动控制，右键 → 以管理员身份运行。

---

## 会不会被 Windows Defender 拦截？

工具本身不含任何恶意代码，但它会：

- 调用 `takeown` / `icacls` 修改系统文件权限
- 替换 `System32` 下的文件
- 调用 `DISM` / `SFC`

这些行为**可能**触发启发式告警。如果被拦截，请检查文件来源（本仓库）后选择允许，或临时添加排除项。

---

## 支持 Windows Server 吗？

支持。`sppsvc` 在 Server 上同样存在，修复逻辑一致。

但 Server 版本的授权模型（KMS / MAK / 零售）与客户端不同，诊断页的 GVLK 对照表只覆盖客户端版本，Server 会显示"不在对照表中"，这不影响文件修复。

---

## 日志在哪里？

- 工具内输出：点「保存日志」导出到桌面
- DISM 详细日志：`C:\Windows\Temp\dism-actfix.log`
- SFC 详细日志：`C:\Windows\Logs\CBS\CBS.log`
- 原文件备份：`C:\Windows\Temp\ActivationFixBackup\`
